OS Structure

4 Components

  • Hardware – CPU, Memory, I/O
  • OS – controls/coordinates hardware use
  • Applications – use resources to solve problems
  • Users – people, machines, computers

OS Definition

Interface between user and hardware. Resource allocator + control program.

OS Views

  • User view: convenience, ease, performance
  • System view: resource allocator, efficiency

Computer Startup

Bootstrap Program

  • Stored in ROM (BIOS) or EEPROM (firmware)
  • Initializes CPU registers, device controllers, memory
  • Loads OS kernel into memory
  • Kernel = central part of OS

Storage Hierarchy (fast→slow)

  • Registers → Cache → Main Memory (RAM) → SSD/HDD → Optical → Tape
  • Volatile: registers, cache, RAM
  • Non-volatile: HDD, SSD
  • Caching: copying data from slower to faster storage

System Architecture

Single-Processor

One main CPU, may have special-purpose processors

Multiprocessor (Parallel)

  • SMP – all CPUs equal, share memory, each has own registers+cache
  • Asymmetric – boss (master) assigns tasks to slaves
↑ Throughput Economy of scale ↑ Reliability

Clustered Systems

  • Multiple systems sharing storage (SAN)
  • Symmetric: all nodes run apps, monitor each other
  • Asymmetric: one node on hot-standby

Multiprogramming vs Multitasking

Multiprogramming

Multiple programs in memory; CPU switches when one waits for I/O. Maximizes CPU use.

Multitasking (Time-Sharing)

CPU rapidly switches so users perceive simultaneous execution.

  • Response time < 1 second
  • Uses virtual memory if process doesn't fit in RAM
  • Swapping: moves processes in/out of memory

DMA

Direct Memory Access — device controller transfers data blocks directly to main memory without CPU. 1 interrupt per block (not per byte).

Environments & Virtualization

Cloud Types

  • Public – open to all (pay per use)
  • Private – company's own
  • Hybrid – both

Service Models

  • SaaS – apps over internet (Word Online)
  • PaaS – software stack (database server)
  • IaaS – servers/storage (backup)

Virtualization

OS runs guest OSes. VMM (Virtual Machine Manager) provides services. Emulation = slow (different CPU). VMware, Xen.

OS Services

  • UI – GUI, CLI, touch
  • Program Execution – load & run programs
  • I/O Operations – manage device access
  • File-system – create, delete, read, write, permissions
  • Communications – shared memory or message passing
  • Error Detection – detect & correct errors
  • Resource Allocation – CPU, memory, I/O devices
  • Accounting – track resource usage
  • Protection & Security – control access, authenticate

System Calls

Programming interface to OS services. Written in C/C++. Programs access OS via system calls.

IPC Communication

Shared Memory

Processes share a memory region. Fast. User-controlled. Needs synchronization.

Message Passing

OS-mediated. Good for networked computers. send() + receive().

Direct vs Indirect

  • Direct: name each other explicitly. 1 link per pair.
  • Indirect: via mailboxes (ports). Many processes can share a link.

Sync vs Async

  • Blocking (sync): sender/receiver waits
  • Non-blocking (async): send and continue

Buffer Capacity

  • Zero: sender must block (rendezvous)
  • Bounded: wait if full
  • Unbounded: sender never waits

Pipes, Sockets, RPC

Pipes

  • Ordinary: parent-child only, unidirectional
  • Named: no parent-child needed, bidirectional possible

Sockets

IP address + port number = socket identifier.

  • Telnet: port 23 | FTP: 21 | HTTP: 80
  • e.g. 161.25.19.8:1625

RPC (Remote Procedure Call)

  • Client calls remote procedure as if local
  • Stub: client-side proxy, marshalls parameters
  • Marshalling: packing parameters into message
  • Server stub unmarshals, runs procedure

Process Concept

Program vs Process

  • Program: passive, stored on disk (executable file)
  • Process: active, program loaded into memory
  • 1 program → many processes (e.g., multiple Chrome tabs)

Process Memory Layout

  • Text – program code
  • Data – global variables
  • Heap – dynamic allocation (runtime)
  • Stack – function params, return addresses, local vars

Process States

New→ Ready→ Running→ Waiting
Terminated

PCB & Threads

Process Control Block (PCB)

  • Process state
  • Program counter (next instruction)
  • CPU registers
  • CPU scheduling info (priority, queue pointers)
  • Memory management info
  • Accounting info (CPU time, clock time)
  • I/O status (devices allocated, open files)

Context Switch

CPU saves state of old process, loads state of new process. Pure overhead — no useful work done.

Threads

Sequence of instruction execution. Multi-threaded → PCB stores multiple program counters.

Process Operations

Creation (UNIX)

  • fork() – creates new child process
  • exec() – replaces memory with new program
  • wait() – parent waits for child to terminate
  • Child = duplicate of parent or has new program

Termination

  • exit() – normal termination
  • abort() – parent kills child
  • Zombie: terminated but parent not called wait()
  • Orphan: parent terminated without wait()
  • Cascading: if parent dies, all children terminated

Producer-Consumer

  • Bounded buffer: producer waits if full, consumer waits if empty
  • Unbounded: consumer may wait, producer never waits

⚡ CPU Scheduling — Formulas (HIGH EXAM PRIORITY)

Key Formulas

Turnaround = Completion − Arrival
Waiting = Turnaround − Burst
Response = First run − Arrival
Avg Waiting = Σ(Waiting) / n

FCFS

Non-preemptive. FIFO order. Simple.

WT(P1)=0, WT(P2)=BT(P1), WT(P3)=BT(P1)+BT(P2)

Convoy effect — short jobs wait for long ones

SJF

Shortest burst first. Optimal avg wait.

  • Non-preemptive: run to completion
  • Preemptive (SRTF): preempt if new arrival has shorter remaining time
WT = Start time − Arrival time

Round Robin (RR)

Preemptive. Each process gets time quantum q.

  • Uses FIFO queue, context switch at end of quantum
  • If q → ∞ behaves like FCFS
  • If q → 0 high overhead

Preemptive vs Non-Preemptive

  • Preemptive: CPU can be taken from running process (RR, preemptive SJF)
  • Non-preemptive: process keeps CPU till done or waiting (FCFS, SJF)

Dispatcher

Gives CPU control to selected process. Performs context switch + jump to restart. Dispatch latency = time to stop one and start another.

At t=1: P2 arrives (burst 4 < P1's remaining 7) → preempt P1. At t=5: P4 arrives (5 < P1's remaining 7) → P4 runs. At t=10: P1 resumes. P3 runs last.

Waiting time formula for SRTF: WT = (time process starts running for last time) − Arrival − (already-run bursts before waiting)

WT(P1) = 10 − 1 = 9  |  WT(P2) = 1 − 1 = 0  |  WT(P3) = 17 − 2 = 15  |  WT(P4) = 5 − 3 = 2
